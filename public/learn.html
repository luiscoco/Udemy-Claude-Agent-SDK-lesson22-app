Turn an application function into a tool the agent can call.

Application labWhat you will learnHow to runArchitecture & workflowCode walkthrough
01

Define the four tool parts

Give tool() a name, a useful description, a Zod input schema and an async handler. The schema types the handler arguments and validates inputs.

02

Run a server in your application

createSdkMcpServer wraps the handlers in-process. The Claude Code runtime remains a child process and the model/API services are remote; in-process describes the custom MCP server.

03

Register and approve the full name

mcpServers.weather supplies the namespace in mcp__weather__get_temperature. allowedTools pre-approves that name; the wildcard mcp__weather__* approves all registered weather tools.

04

Call real weather services

Ask for San Francisco and Madrid. Inspect real handler arguments, HTTP status, observation times and returned content. The app uses live Open-Meteo data and never substitutes a saved forecast.

05

Add optional parameters

The second tool uses hours.optional(). The handler applies args.hours ?? 12. Compare omitted hours with an explicit value of six using actual handler evidence.

06

Wrap your own endpoint

A third tool calls this app’s read-only /api/course endpoint over real local HTTP. It is a classroom endpoint, so no private database or production integration is implied.
